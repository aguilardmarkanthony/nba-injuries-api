# Production release verification: 2.3.0

Verified on October 12, 2026. These results describe the snapshot observed during the release, not fixed future injury counts or a latency guarantee.

- Implementation: [PR #1](https://github.com/aguilardmarkanthony/nba-injuries-api/pull/1), merged as `c307793a2a4ded20832db36af9609047e851facc`.
- [Main CI](https://github.com/aguilardmarkanthony/nba-injuries-api/actions/runs/38169533441) passed on Python 3.11 and 3.13. The suite contains 90 tests; lint, formatting, dependency compatibility, specification drift, and runtime dependency audit checks passed.
- Render deployed version `2.3.0` from GitHub `main`. Its saved health-check path is `/v1/health`.
- The existing RapidAPI v1 definition was updated from `rapidapi-import.json`. All four documented endpoints appear in the public listing.
- The listing descriptions and GitHub website link were saved. The public documentation was saved from `docs/rapidapi.md` and read back with an exact match.

## Authenticated gateway checks

All 11 checks passed through `nba-injuries-api.p.rapidapi.com` using the existing subscription.

| Request | Result |
| --- | --- |
| `/v1/health` | 200; version `2.3.0` |
| `/v1/injuries` | 200; 132 player entries across 30 teams; fresh cache |
| `/v1/injuries?team=GSW` | 200; 3 entries; canonical team `GSW` |
| `/v1/injuries?team=GS` | 200; same 3 entries and player identity |
| `/v1/injuries?team=NOP` | 200; 1 entry; canonical team `NOP` |
| `/v1/injuries?team=NO` | 200; same entry and player identity |
| `/v1/injuries?team=INVALID` | 400; `INVALID_TEAM` |
| `/v1/injuries?team=` | 400; `INVALID_TEAM` |
| `/v1/teams` | 200; 30 directory entries |
| `/v1/player/search?name=James` | 200; 2 matches |
| `/v1/player/search?name=%20%20` | 400; `INVALID_SEARCH` |

Observed warm request durations ranged from 221 to 1,343 milliseconds. These measurements followed deployment and do not measure idle cold starts.

## Authentication and monitoring

Three additional direct-origin checks returned 401 as expected: no credentials, `free-demo-key`, and `pro-demo-key` in the `X-API-Key` header.

The existing RapidAPI daily health monitor had historical failures predating this release. A manual execution of that same monitor succeeded after deployment, checking that `/v1/health` returned 200. Its daily schedule was preserved. This does not establish that future cold-start checks will pass on Render Free.

The health route measures liveness. Source readiness and snapshot freshness require `/v1/ready` and response cache metadata. See [ROADMAP.md](ROADMAP.md) for the proposed always-on hosting and durable cache improvements.
